  Evaluation

  The requirements are clear and fit well with .NET 8 built-ins. The parts that
  need care are:

  - Alert semantics. "Last alert date" only works if you define how feed items
    are timestamped, what happens on a subscription's first run, and what
    happens to items with no publication date.
  - Delivery vs. storage. Storing the alert before sending is the right call,
    but it means a delivery log with retries. A failed Slack post must not lose
    the alert.
  - Abuse surface. Users can enter arbitrary email addresses and webhook URLs,
    and admins enter arbitrary feed URLs. Without verification and SSRF
    protection, the app can be used to spam third parties or probe internal
    hosts.
  - Overlapping runs. The scheduler must not process the same subscription twice
    if runs overlap or if you later scale out.

  Data model (EF Core code-first)

  - ApplicationUser (Identity) with IsActive
  - NotificationTarget: user, type (Email/Slack), address or webhook,
    IsVerified, IsEnabled
  - NewsSource: name, URL, IsActive, LastFetchedAt, ETag, LastModified
  - Subscription: user, name, IsEnabled, Frequency (minutes), LastAlertAt,
    LastRunAt
  - Join tables: SubscriptionSource, SubscriptionTarget
  - SubscriptionKeyword: term, Include/Exclude
  - FeedItem: source, item GUID, link, title, summary, published date. Unique on
    (source, GUID).
  - Alert: subscription, created at, and AlertItem rows linking to FeedItem
  - AlertDelivery: alert, target, status, attempts, last error, sent at (drives
    retries)

  Alert engine

  1. Select due subscriptions: enabled, owner active, at least one active
     source, and now >= LastRunAt + Frequency. A 1-minute timer tick handles
     1-minute frequencies.
  2. Fetch once per source: distinct sources across all due subscriptions. Use
     conditional GET (ETag/Last-Modified), a timeout, and bounded parallelism.
     Parse with System.ServiceModel.Syndication.SyndicationFeed, which is built
     into .NET 8 and reads both RSS and Atom.
  3. Upsert FeedItems by (source, GUID) so repeated runs don't duplicate items.
  4. Per subscription: take items from its sources published after LastAlertAt.
  5. Keyword filter: case-insensitive match against title and summary. Items
     must match all of the include terms (or any, depending on your choice) and
     none of the exclude terms.
  6. Store: in one transaction, create the Alert and AlertItems and advance
     LastAlertAt and LastRunAt.
  7. Dispatch: for each target, IAlertChannel.SendAsync. Write an AlertDelivery
     row per target. Retry with backoff. A failed delivery never rolls back the
     alert.
  8. Concurrency: take a SQL Server application lock (sp_getapplock) per run so
     only one engine instance processes at a time.

  Channels are a Type-keyed registry of IAlertChannel implementations. Adding a
  new channel means one new class plus one new enum value.

  Security and admin

  - ASP.NET Core Identity with roles Admin and User. /admin/** requires the
    Admin role.
  - Email targets need a confirmation link before they can receive alerts.
  - Slack targets must match the hooks.slack.com pattern.
  - Feed URLs must be http/https and must not resolve to private or loopback
    addresses.
  - SMTP credentials and webhook secrets go in user secrets or environment
    variables, not in source.
  - Deactivating a user is a flag, not a delete. The engine skips inactive
    users. Deleting a user cascades to their subscriptions and targets.

  - Scheduler: a separate Worker service that shares the SQL Server database

  Engine run, every minute

  1. Select enabled subscriptions that are due. Owner must be active and sources
     must be active.
  2. Fetch each distinct source once, using ETag and Last-Modified conditional
     GETs with timeouts.
  3. Parse with SyndicationFeed and upsert FeedItem rows, unique on source plus
     GUID.
  4. For each subscription, take items published after LastAlertAt (undated
     items use first-seen time).
  5. Apply the keyword filter.
  6. In one transaction, create the Alert and its AlertItems and advance
     LastAlertAt and LastRunAt.
  7. Dispatch to each target and record an AlertDelivery row. Retry with
     backoff. A failed send never rolls back the stored alert.
  8. Take a SQL Server application lock per run so overlapping runs cannot
     double-send.

  The prototype is a .NET 8 console app. It reads RSS feeds, applies keyword
  filters, and prints the matching items. It has no database, no users, and no
  web UI. The filter and fetch code is written so that later milestones can
  reuse it unchanged.

  Phase 1: Console prototype

  - Project: CustomAlertManager.Prototype, a console app in the solution.
  - Input: feed URLs, include keywords, exclude keywords, and a --since time.
    These come from appsettings.json or command-line arguments. Example: --feed
    https://feeds.bbci.co.uk/news/rss.xml --include "ukraine,election" --exclude
    "sport" --since 2h.
  - Fetch: HttpClient with a timeout. Each feed is downloaded once, even if
    several subscriptions use it.
  - Parse: System.ServiceModel.Syndication.SyndicationFeed, which handles RSS
    and Atom.
  - Filter: the same rules we agreed on. Case-insensitive. An item matches if it
    contains any include term and no exclude term. Undated items use the
    current time.
  - Output: a console table or list with title, source, published time, and
    link.
  - Structure: IFeedFetcher, IKeywordFilter, and IAlertChannel interfaces from
    day one. The console output is the first IAlertChannel.
  - Tests: an xUnit project covering the filter rules and parsing a saved sample
    RSS file. The sample lives in the repo, so tests don't need the network.

  Done when: you can run the console app against the BBC feed with keywords and
  see correct matches, and the tests pass.

  Phase 2: Persist and schedule

    deduplicate items by source and GUID.
  - Add the Worker project. It runs the same engine on a one-minute timer and

  - Add the SQL Server application lock so runs cannot overlap.

  Phase 3: Delivery
